# Day 8 — 打字卡顿修复 + Loading 状态修复

## 问题诊断

### Bug 1: 打字卡顿
每键触发链: `doAfterTextChanged` → `TextChanged` Intent → `.copy()` → `_state.value = ` (StateFlow 发射)
→ **`persistState()` (Bundle 序列化)** → `render()` 全量扫描 → `notifyDataSetChanged()`

三大性能杀手:
1. **`persistState()`** — 每键序列化到 Bundle，成本最高
2. **`imageGridAdapter.updateData()` → `notifyDataSetChanged()`** — 图片未变却每帧刷新
3. **`render()` 无过滤** — 所有 UI 操作无条件执行

### Bug 2: Loading 永不消失
`handleClickPublish()` 设 `isLoading = true` 后从未设回 false。
且无任何 UI 守卫，发布中仍可编辑。

## 修复内容

### PublishViewModel.kt
- `handleTextChanged`: **移除 `persistState(newState)` 调用**，文本持久化由 Activity.onSaveInstanceState 兜底
- `handleClickPublish` 重写:
  - `isLoading` guard 防重复点击
  - `viewModelScope.launch { delay(2000); resetState }` 模拟发布流程
  - 发布完成后 `PublishState()` 重置全部字段
- 新增 import: `kotlinx.coroutines.delay/launch`, `androidx.lifecycle.viewModelScope`

### MainActivity.kt
- `render()` 重写（Day 8 重构）:
  - **loading 守卫**: `ktg.isEnabled`, `btnPublish.isEnabled`, `barTopic/Mention/Emoji/Photo.isEnabled` 全部联动 `!loading`
  - **图片列表跳过更新**: `if (state.selectedImages !== lastImageList)` 引用比较，打字时不触发 `notifyDataSetChanged`
  - **Toast 发布成功**: `wasLoading→!loading` 状态转换检测 + 表单清空确认
- 新增字段: `wasLoading: Boolean`, `lastImageList: List<Uri>`

## 架构决策
- TextChanged 不 persistState：打字是最高频操作，persistState 的 Bundle 序列化成本远大于收益
- 文本持久化降级：SavedState → Activity.onSaveInstanceState（EditText 自身 saveEnabled=true 已覆盖旋转）
- === 引用比较优化 render：`data class.copy` 对未改字段保持原引用，天然支持 O(1) 去重
- Loading UI 守卫模式：在主渲染函数统一处理，而非分散到各 onClick 中

# Day 9 — 动态相册上限 + 左上角"取消"按钮

`PickMultipleVisualMedia(9)` 在 `registerForActivityResult` 时写死 maxItems=9。

- 替换 `registerForActivityResult(PickMultipleVisualMedia(9))` → `PickMultipleVisualMediaDynamic()`

### activity_main.xml

### strings.xml

## 架构决策
- 自定义 ActivityResultContract 而非 hack：`PickMultipleVisualMedia` 的 maxItems 是构造参数无法运行时变更，自定义合约是最干净的方案

# Day 12 — 拖拽空白区修复 + 自定义相册选择器（方案 B）

## 问题

### Bug: 拖到空白区域静默失败
`clearView` 中 `findChildViewUnder` 返回 null 时直接 return，用户把图片拖到九宫格外围松手后无反应。

### 功能升级: 图片选择改为自建相册
原系统 Photo Picker 不支持跨会话标记已选图片。用户要求：第二次打开相册时，已选照片应显示勾选标记。

## 修复

### 拖拽空白区吸附 (MainActivity.kt)
- `clearView` 改为两步查找：
  1. 先 `findChildViewUnder(centerX, centerY)` 找直接命中
  2. 若 null → 根据 `cellW = (rv.width - padding) / 3`、`cellH = itemView.height`、行列公式手动算出最近合法 position
- 边界 clamp：col 限制 0..2，row 限制 >=0，position clamp 到 0..imageCount-1

### 自定义相册架构

```
MainActivity
  └─ pickMultipleMedia = registerForActivityResult(GalleryPickerContract())
       └─ launch(PickConfig(maxSelectable=N, preSelectedIds=[...]))
            └─ GalleryPickerActivity
                 ├─ query MediaStore.Images（按 DATE_MODIFIED DESC）
                 ├─ GridLayoutManager(3列)
                 ├─ 每张照片显示：缩略图 + 选中遮罩 + 勾选图标
                 ├─ 点击切换选中/取消（上限检查）
                 └─ "完成" → setResult(RESULT_OK, ArrayList<Uri>)
```

### 新增文件
| 文件 | 职责 |
|---|---|
| `GalleryPickerContract.kt` | ActivityResultContract, PickConfig 数据类 |
| `GalleryPickerActivity.kt` | 自定义相册 UI，加载 → 勾选 → 返回 |
| `GalleryPickerAdapter.kt` | 网格适配器，GalleryPhoto 数据模型 |
| `activity_gallery_picker.xml` | 顶部栏 + RecyclerView 布局 |
| `item_gallery_photo.xml` | 单张照片：缩略图 + 遮罩 + 勾选 |
| `ic_check_circle.xml` | 矢量勾选图标 |

### PublishViewModel 行为变更
- `handleImagesPicked` 从"追加+去重"改为"完整替换"
  - 原因：自定义相册返回的是完整选中列表（含旧图+新图，部分旧图可能被取消）
  - `uris.subList(0, 9)` 截断 → 直接设为 `selectedImages`
  - 同列表短路 `if (safetyImages == _state.value.selectedImages) return`

### 已删除
- `PickMultipleVisualMediaDynamic.kt` — 被 GalleryPickerContract 替代
