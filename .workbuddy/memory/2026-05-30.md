# Day 8 — 打字卡顿修复 + Loading 状态修复

## 问题诊断

### Bug 1: 打字卡顿
每键触发链: `doAfterTextChanged` → `TextChanged` Intent → `.copy()` → `_state.value = ` (StateFlow 发射)
→ **`persistState()` (Bundle 序列化)** → `render()` 全量扫描 → `notifyDataSetChanged()`

三大性能杀手:
1. **`persistState()`** — 每键序列化到 Bundle，成本最高
2. **`imageGridAdapter.updateData()` → `notifyDataSetChanged()`** — 图片未变却每帧刷新
3. **`render()` 无过滤** — 所有 UI 操作无条件执行

### Bug 2: Loading 永不消失
`handleClickPublish()` 设 `isLoading = true` 后从未设回 false。
且无任何 UI 守卫，发布中仍可编辑。

## 修复内容

### PublishViewModel.kt
- `handleTextChanged`: **移除 `persistState(newState)` 调用**，文本持久化由 Activity.onSaveInstanceState 兜底
- `handleClickPublish` 重写:
  - `isLoading` guard 防重复点击
  - `viewModelScope.launch { delay(2000); resetState }` 模拟发布流程
  - 发布完成后 `PublishState()` 重置全部字段
- 新增 import: `kotlinx.coroutines.delay/launch`, `androidx.lifecycle.viewModelScope`

### MainActivity.kt
- `render()` 重写（Day 8 重构）:
  - **loading 守卫**: `ktg.isEnabled`, `btnPublish.isEnabled`, `barTopic/Mention/Emoji/Photo.isEnabled` 全部联动 `!loading`
  - **图片列表跳过更新**: `if (state.selectedImages !== lastImageList)` 引用比较，打字时不触发 `notifyDataSetChanged`
  - **Toast 发布成功**: `wasLoading→!loading` 状态转换检测 + 表单清空确认
- 新增字段: `wasLoading: Boolean`, `lastImageList: List<Uri>`

## 架构决策
- TextChanged 不 persistState：打字是最高频操作，persistState 的 Bundle 序列化成本远大于收益
- 文本持久化降级：SavedState → Activity.onSaveInstanceState（EditText 自身 saveEnabled=true 已覆盖旋转）
- === 引用比较优化 render：`data class.copy` 对未改字段保持原引用，天然支持 O(1) 去重
- Loading UI 守卫模式：在主渲染函数统一处理，而非分散到各 onClick 中

- `clearView` 改为两步查找：

                 ├─ 每张照片显示：缩略图 + 选中遮罩 + 勾选图标
                 ├─ 点击切换选中/取消（上限检查）
