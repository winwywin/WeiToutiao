## fix: 拖拽松手后图片位置跳变（交换而非移动）

### 根因分析
拖拽松手时出现"图片 A 和 B 交换位置"而非"其它图片依次后移"的现象，完整链路如下：

1. 拖拽中 `previewOnItemMove` 做单步 `Collections.swap` + `notifyItemMoved`，本地顺序已正确
2. 松手 `clearView` → `getImages()` 收集最终顺序 → `ReorderImages` → ViewModel → 新 State emit
3. `render()` 里 `state.selectedImages !== lastImageList`（引用比较）为 true（两个不同 ArrayList 实例）
4. 触发 `updateData()` → `notifyDataSetChanged()` → RecyclerView 重新测量，打断 ItemTouchHelper 松手动画
5. 视觉上：ItemTouchHelper 还在播放回弹动画，RecyclerView 同时刷新，出现位置跳变/交换感

### 修复
**MainActivity.kt**：
- `clearView` 里提交 `ReorderImages` 前，先 `lastImageList = finalOrder`（提前同步缓存引用）
- 九宫格刷新判断从引用比较 `!==` 改为**内容比较** `!=`（Uri List 的 equals 是内容比较），确保内容相同时不触发 `notifyDataSetChanged`

```kotlin
// 改动1: clearView
val finalOrder = ArrayList(imageGridAdapter.getImages())
lastImageList = finalOrder  // ← 先同步，防止 render() 二次刷新
viewModel.sendIntent(PublishIntent.ReorderImages(finalOrder))

// 改动2: render()
if (state.selectedImages != lastImageList) {  // != 内容比较，而非 !== 引用比较
    imageGridAdapter.updateData(state.selectedImages)
    lastImageList = state.selectedImages
}
```

## feat: DraftManager JSON → SQLite 迁移（满足题目硬性要求）

### 动机
审计三份题目文档发现硬性要求：「本地存储 → SQLite → 原生 SQLiteOpenHelper（手写 SQL），禁用 Room」。
原 DraftManager 使用 JSON 文件存储，违背工具约束。

### 迁移方案

| 维度 | 迁移前 (JSON) | 迁移后 (SQLite) |
|------|-------------|----------------|
| 存储引擎 | `filesDir/wtt_draft.json` | `databases/wtt_draft.db` |
| 元数据 | JSON field | `draft_meta` 表（单行 id=1） |
| 图片路径 | JSON array | `draft_images` 表 (file_path, sort_order) |
| Span 描述符 | JSON array | `draft_spans` 表 (serialized, sort_order) |
| 图片文件 | `filesDir/draft_images/` | 不变 |

### 新增文件
- **DraftDatabaseHelper.kt** — `SQLiteOpenHelper`，3 张表，手动 `execSQL`，无 Room 注解

### 重写文件
- **DraftManager.kt** — 6 个公开 API 签名完全不变，内部全面替换为 SQLite CRUD：
  - `hasDraft()` → `SELECT COUNT(*) FROM draft_meta`
  - `getDraftMeta()` → `SELECT text, saved_at + 子查询 image COUNT`
  - `loadDraft()` → 三表联查 → 路径存在性校验 → `DraftData`
  - `saveDraft()` → 清旧 → 批量 `INSERT`（事务包裹，保证原子性）
  - `deleteDraft()` → 三表 `DELETE`（事务包裹）
  - `estimateSize()` → DB 文件大小 + 图片目录大小

### 兼容性
- ViewModel 和应用层零改动：DraftManager 构造函数、方法签名、数据类完全不变
- 旧 JSON 文件与 SQLite 独立共存（首次迁移后 JSON 文件变历史遗留，可手动删除）

## refactor: 双层草稿机制 — 主动保存 + 防抖保存

### 用户诉求
1. onPause 每次都存导致大量相似重复草稿
2. 退出时没有弹窗确认（用户可能不想保存就离开了）
3. 需要区分「主动保存」（用户确认）和「防抖保存」（onPause 临时兜底）

### 双层草稿机制设计

| 机制 | 触发时机 | 存储 | 后续行为 |
|------|---------|------|---------|
| **主动保存** | 退出弹窗点「保存」 | is_temporary=0（永久） | 立即落盘 |
| **防抖保存** | onPause | is_temporary=1（临时） | onResume→全部删除 / onStop→全部升级为永久 |

### 数据库
**DraftDatabaseHelper.kt** v2→v3：
- 新增 `is_temporary INTEGER NOT NULL DEFAULT 0`
- onUpgrade 采用 ALTER TABLE ADD COLUMN（不 DROP 重建，保留已有草稿）

**DraftManager.kt**：
- `saveDraft()` → `internalSave(isTemporary=false)` 永久草稿
- 新增 `saveTemporaryDraft()` → is_temporary=1
- 新增 `markAllTemporaryPermanent()` → UPDATE is_temporary=1→0
- 新增 `deleteAllTemporaryDrafts()` → DELETE WHERE is_temporary=1 + 清理图片
- `getAllDrafts()` 加 `WHERE is_temporary=0` 过滤临时草稿

### MVI 层
**PublishIntent**：
- 新增 `ConfirmSaveAndExit`（弹窗点保存）
- 新增 `ConfirmDiscardAndExit`（弹窗点不保存）
- 删除 `ForceSave`（不再由 Intent 驱动，改为 ViewModel 内部生命周期方法）

**PublishViewModel**：
- `ExitAction` 枚举（Save/Discard），标记用户显式退出选择
- `launchingInternalActivity` 标记，防止内部 Activity 跳转触发误升级
- `onActivityPause()`：explicitExitAction!=null 时跳过 → 否则存临时草稿
- `onActivityResume()`：删除所有临时草稿（用户回来了，数据没丢）
- `onActivityStop()`：launchingInternalActivity=true 时跳过 → 否则临时草稿升级为永久
- `handleConfirmSaveAndExit()`：存永久草稿 + 设置 ExplicitAction=Save
- `handleConfirmDiscardAndExit()`：设置 ExplicitAction=Discard
- `hasContent()`：公开方法供 Activity 判断是否弹退出确认框
- `notifyInternalActivityLaunch()`：启动内部 Activity 前调用

**MainActivity**：
- `onBackPressed()` / `btnBack.onClick` → `showExitConfirmDialog()`

## fix: 图片预览点击失效 + 相册返回顺序不对

### Bug 1：点击图片无法预览
**根因**：`ImageGridAdapter.bindImageHolder()` 中 lambda 捕获的 `position` 参数在数据变更后
（拖拽排序 `previewOnItemMove` / `notifyItemMoved`）变陈旧，点击时可能拿到错误的位置或越界 index。

**修复**：
- `btnDelete` 和 `imageView` 的 click listener 改用 `holder.adapterPosition` 实时获取
- 加 `NO_POSITION` 守卫，防极端竞态

```kotlin
// 修复前
holder.imageView.setOnClickListener { mOnImageClickListener?.invoke(position) }

// 修复后
holder.imageView.setOnClickListener {
    val pos = holder.adapterPosition
    if (pos != RecyclerView.NO_POSITION) mOnImageClickListener?.invoke(pos)
```
